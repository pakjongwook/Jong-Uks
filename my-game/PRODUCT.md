# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

delegated: 정적 HTML/CSS/JS, 페이지 하나당 파일 하나(`*.html`), 프레임워크와 빌드 단계 없음. 파일을 더블클릭하면 바로 브라우저에서 열리고, 연습 과정에서 코드를 한눈에 읽을 수 있어서 이 방식을 골랐다. 외부 리소스는 Google Fonts 정도만 쓴다.

## Users

포트폴리오 열람자. 만든 사람을 알아보고 그 사람이 만든 미니게임을 직접 눌러 보려고 들어오는 사람들이다. 짧게 방문하고, 휴대폰으로 보는 경우가 많다고 가정한다.

## Product Purpose

자기소개 페이지와 브라우저 미니게임을 모아 둔 개인 포트폴리오. 지금은 게임 만드는 법을 익히는 연습장이며, 페이지 하나하나가 연습 결과물이다. 열람자가 페이지를 열자마자 바로 플레이할 수 있고 그 경험이 즐거우면 성공이다.

## Positioning

만든 사람 본인을 드러내는 포트폴리오다. 장기적인 꿈은 "마음이 힘들고 아픈 사람에게 위로가 되는 게임"을 만드는 것이다(`index.html`). 다만 그 꿈이 이 프로젝트의 현재 목표는 아니다. 지금 단계는 연습이다.

## Operating Context

- `index.html`: 자기소개("🌈 나를 소개합니다!")와 취미, TMI, 인사하기 버튼, 5초 안에 10번 누르기 클릭 도전.
- `arcade.html`: 네온 스타일 "GAME START" 화면과 쉬움, 보통, 어려움 난이도 버튼. 아직 실제 게임과 연결되지 않음(누르면 "준비 중" 안내만 표시).
- `rps.html`: 가위바위보 게임, 밝은 오락실 캐비닛 스타일.
- `bo.html`: 가위바위보 게임, 밤의 숲 스타일. 컴퓨터가 무작위로 고르고 승패를 표시함.
- `mole.html`: 두더지 잡기 게임, 밝은 잔디밭 스타일. 3×3 구멍 9개, 점수와 남은 시간(30초), "게임 시작" 버튼과 카운트다운이 있음. 게임 중에는 랜덤 동물(토끼·고양이·강아지·개구리·돼지·곰·병아리, 각자 이모지 말풍선)이 랜덤 구멍에서 한 마리씩 1초간 올라옴. 동물을 누르면 💥 이펙트와 함께 사라지고 1점(한 마리당 한 번만), 빈 구멍은 반응 없음. 30초가 끝나면 동물·클릭이 멈추고 "게임 오버! 최종 점수 ○점" 결과 카드와 "다시 하기"(0점·30초로 카운트다운부터 새로 시작)가 나옴.
- 화면 문구는 한국어(`lang="ko"`)이며, 친근한 말투에 이모지를 많이 쓴다.

## Capabilities and Constraints

- 서버, 계정, 저장 기능 없음. 모든 동작이 브라우저 안에서 끝난다.
- `index.html`의 "🕹️ 내가 만든 게임" 목록에서 네 게임 페이지로 가고, 각 게임 페이지 왼쪽 위 "처음으로" 링크로 돌아온다. 게임 페이지끼리는 직접 연결하지 않는다.
- 정해지지 않은 것: 공개 배포 위치(호스팅), 게임별 공통 스타일을 둘지 여부.

## Brand Commitments

- 만든 사람 본인의 목소리를 쓴다. 밝고 친근하며 이모지를 넉넉히 넣는 한국어 문구(`index.html` 기준).
- 정해진 로고나 공통 비주얼 아이덴티티는 없다. 페이지마다 다른 스타일을 연습하고 있다.

## Evidence on Hand

- 실제로 있는 콘텐츠: 위 네 개 HTML 페이지와 `index.html`에 적힌 자기소개 내용.
- 없는 것: 방문자 수, 후기, 수상 경력, 외부 평가. 앞으로 작업할 때 이런 것을 지어내지 않는다.

## Product Principles

1. 열자마자 플레이할 수 있어야 한다. 설치, 로그인, 설명서가 필요 없게 한다.
2. 만든 사람이 드러나야 한다. 문구와 디테일에 본인의 말투와 취향을 남긴다.
3. 연습 결과물답게 작고 완결되게 만든다. 페이지 하나에 아이디어 하나를 끝까지 완성한다.
4. 휴대폰에서도 문제없이 동작해야 한다. 열람자가 링크를 휴대폰으로 열 가능성이 높다.
